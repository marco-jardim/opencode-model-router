### 2.1.1 Registry (`sessions.ts`)

- `rememberDispatch(childSessionID, { facts, agent, model, variant?, tier?, acceptance?, parentSessionID?, attemptId?, decisionID?, step? }, nowMs?)`, `lookupDispatch`, `touchDispatch`, `forgetDispatch`, `forgetDispatchesOf(parent)` (returns the removed records), `sweepDispatches(nowMs?, ttlMs?)`, `dispatchCount`, `resetDispatchRegistry` (tests).
- **Module scope** (A3), deliberately unlike the per-instance `createSessionStore`. TTL = `DEFAULT_IDLE_TTL_MS` (1 h) from the last touch, swept from the existing idle sweeper (`index.ts` adds one sweeper line). Bounded to `MAX_DISPATCH_RECORDS = 2000` (oldest registration dropped).
- A re-registration of the same child (a resume, or a ladder attempt) bumps `attemptIndex` (display only). **The default `attemptId` is `${childSessionID}:${attemptIndex}:${nonce}-${seq}`, `seq` a process-wide counter and `nonce` 8 random hex digits drawn once per process (QA-2.1-1, QA-2.1-R2-2)**: the index restarts at 0 after an eviction, and the store remembers scored attempt ids, so `${child}:${index}` alone could name two attempts and drop the second one's outcome. `attemptId` can still be supplied.
- **Additions beyond the plan's argument list** (all optional, forward-compatible): `attemptId`, `decisionID` (so verdict/refusal rows can reference the 2.2 decision row, 1.3 handoff), `step` (`LadderStepKind`, default `dispatch`; `AttemptSignal` needs it and 2.3 ladder attempts will pass `variant|retry|escalate`). `acceptance` is typed `"deterministic" | "grader" | "none" | null` (the `routing.detection` keys, QA-2.1-13) and is carried only; ingestion never reads it.
- `facts` is typed `DecisionFacts` (1.3's structural view; 1.2's `TaskFacts` is assignable).

### 2.1.2 Ingest (`ingest.ts`) and 2.1.3 wiring (as of round 1)

**Ingest.**

- `createIngest(deps)` returns `{ onStepEnded, onExecutionEnded, onVerdict, onFalseRefusal, onSessionGone, requestFlush, sweep, dispose }`. `deps = { settings, logger, pricing?, now?, acquire? }`. Handlers never throw: every body is `try/catch` with `logger.warn` (no empty catch). `NOOP_INGEST` is what an adapter without an ingest uses.
- `ingestSettings(cfg, host)` is `null` unless `host === "v2"` and `resolveRouting(cfg, "v2").engine !== "static"`. With `null`, **no bundle is acquired and nothing touches the disk** (§1.2). The bundle (`acquireOutcomes`, A3) is acquired lazily on the first signal that is actually recorded, and a changed `routing.outcomes.path` re-acquires. When the settings turn `null` later (hot reload to static) the next `sweep()` or `requestFlush()` finishes what is pending and releases the bundle (QA-2.1-11); it is re-acquired if the engine comes back.
- Order of checks per signal: registered child → settings non-null → class trusted (`facts.confidence ≥ routing.minClassConfidence`, `facts.class` not empty/`unknown`) → key buildable → record. Registry first because most `session.step.ended` events belong to unregistered sessions (the orchestrator's own) and `loadConfig` costs a fingerprint check. An unkeyable child (no model, malformed model reference) is warned about once per model reference, not per child (QA-2.1-12).
- Key = `makeKey(facts.class, { origin: classifyAgentOrigin(agent, active tier ids), id: agent }, provider, model, variant)`. The registry only holds `facts.class`, so a backend label can never become a key (A19, QA-1.2-27). `model` comes from the registry (the step event carries no model); `variant` = registry variant, else the `#variant` of the model ref.
- **Pricing (QA-2.1-2, QA-2.1-5).** `createCatalogPricing(list, { cacheKey, signal, loadTimeoutMs, ttlMs, retryMs })`: one process-wide table, in-flight load and back-off per `cacheKey` (the location directory), so two plugin instances share them. A loaded table is served at once (stale after the TTL while it reloads in the background); only the first lookup of a cold catalog waits, for at most `loadTimeoutMs` (2 s) and never past `signal`; a failed or timed-out load backs off for `retryMs` (15 s) and a hung load is replaced after that. Absent model, failed or slow load, abort: `unpriced` (A1). After one timeout nobody waits again until a load has succeeded, and a load that timed out stays pending: no second `list()` starts behind it (QA-2.1-R2-4); the first lookup after a timeout, and every later one, answers `unpriced` at once.
- **Step events.** `session.step.ended` and `session.step.failed` (the latter only when it carries a cost or tokens; never a final message) → pricing → then, synchronously, re-check the registry and settings, **check-and-record the event id** (QA-2.1-2) and `recordStep`. The dedupe key is `${outcomesDir}|${eventId}` (QA-2.1-8), in a module-scope LRU (`SEEN_EVENT_CAP = 4096`); an event with no id falls back to a content key. An instance whose own settings are static does not consume an event another instance records. A step whose child was registered again while it waited for pricing (a different attempt id) is skipped, not given to the new attempt (QA-2.1-R2-11).
- **Attempt lifecycle (QA-2.1-6).** A step whose `finish` is not `tool-calls` only sets the attempt's final output: it is held outside the store and recorded as the attempt's final step when the attempt ends: `session.execution.{succeeded,failed,interrupted}` of the child (`onExecutionEnded`), the child's or its parent's deletion, a sweep that finds it idle for 30 minutes, the next attempt of the same child, or `dispose()`. A later step of the same attempt records the held one as a plain step. At the end, an attempt with no held final step is closed (folded as it stands). The last-attempt and held-step maps are keyed by outcomes directory as well. The held steps are shared by every instance of the process: `settle` leaves a step alone when this instance cannot reach the store of its directory (it is static, disposed or writes elsewhere), `sweep` touches only the instance's own directory and drops ownership keys that someone else settled, and a change of outcomes directory settles the old one first (QA-2.1-R2-1, R2-8).
- **Verdicts and refusals (QA-2.1-3, QA-2.1-9).** `recordVerdict` first; a `VerdictRow` only when the store took the verdict (`unverifiable` moves nothing by design and is a row only while its attempt is unscored). A false refusal is one per attempt: a repeat returns before the store (its lifetime counter would grow). A refusal that converts an earlier `pass` records `overrides: "pass"` on its `RefusalRow`; `routing:stats` then does not count that pass as a pass and counts one fail for the attempt (not one per duplicate row), whichever window each row is in; **only the explicit marker converts** (QA-2.1-R2-2). A later pass/fail row replaces an unverifiable row of the same attempt (R2-9), and a refusal that was a variant attempt's first terminal signal is a variant failure, like the store's (R2-3). The pass rate equals the store's. The order independence itself (C5/QA-1.3-6) is the store's.
- A dispatch below `minClassConfidence` (or class `unknown`) gets **no store call and no verdict/refusal row**, so rows and store agree for `routing:stats` (QA-2.1-10). The decision row is 2.2's.
- `onSessionGone(id)`: folds the child's attempt (held final step first) and forgets its registration; also forgets (and folds) every child registered under `id` as parent; requests a flush if a bundle is held.
- Flush (D15): handlers only update memory and `flusher.enqueue`; `requestFlush()` (coalesced, throttled to 30 s by the 1.3 flusher, never awaited, no-op without a held bundle) is called on `session.idle`, `session.deleted` and the v2 idle equivalents `session.execution.*` (`FLUSH_EVENT_TYPES`); `sweep()` (registry TTL, children swept away, idle held steps, `store.sweepAttempts`) runs on the same events and from the idle sweeper. `dispose()` settles this instance's held steps and releases the holder, whose last release flushes.

**Wiring (QA-2.1-7).**

- `index.ts` creates the plugin instance's **one** ingest (v2 only): `settings: () => ingestSettings(cfg, "v2")` (live config), `pricing` from `ctx.routerCatalog` (`createCatalogPricing`, `cacheKey: ctx.directory`), and hands it out through `ctx.routerOnIngest`. Its `dispose` aborts the catalog waits, then disposes the ingest. It also drives the call sites: `ingest?.onFalseRefusal(childSessionID)` right after `trajectoryStore.recordFalseRefusal`, `ingest?.onVerdict(childSessionID, verdictOf(res.verdict))` after `applyDispatchCaveats` (non-skipped verdicts only), `ingest?.sweep()` in the idle sweeper, `ingest?.dispose()` in `dispose`. On v1 `ingest` is `undefined` (D1). The delegate runner is untouched.
- `src/v2.ts` supplies `routerCatalog` (`ctx.model.list({ location: { directory } })`, the call `v2-client.ts` already makes) and `routerOnIngest`, and passes the instance to `registerV2Hooks(ctx, hooks, runtime, { ingest })`. `RouterPluginInput` gains those two optional fields.
- `v2-hooks.ts` (event loop and cleanup only; `execute.before` and the context hook untouched) no longer builds an ingest (`NOOP_INGEST` without one): `session.step.ended`/`session.step.failed` → `ingest.onStepEnded(event)` then `continue`; `session.deleted` → `ingest.onSessionGone` before the unchanged legacy translation; the execution-end events → `ingest.onExecutionEnded(sessionID)`, then `sweep()` and `requestFlush()`. Each call goes through a local `ingesting(...)` wrapper that logs and continues, so a throwing handler cannot skip the legacy translation. `cleanup` disposes the ingest **before** awaiting the event task, so a handler waiting for the catalog is released at once.
- **Merged 1.x modules touched (minimal additions, round 1):** `types.ts` (`RefusalRow.overrides?: "pass"`), `persist.ts` (`parseLogLine` keeps `overrides` when it is `"pass"`), `stats.ts` (a refusal overrides a pass of the same attempt; `refusal()` in `routing-outcomes.stats.test.ts` now builds its own attempt id `:r`, so the existing scenario keeps its meaning). Nothing else under `src\routing\outcomes\*` changed except the new `ingest.ts`.
